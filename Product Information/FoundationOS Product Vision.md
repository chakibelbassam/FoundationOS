# FoundationOS Product Vision

**Intended experience · roadmap to 1.0**

Months after making a Weather app, I can find it, see its source and run it without remembering its framework or start command. FoundationOS gives people and their agents a self-hosted workspace where files survive the tools used to create them.

## People and their workspaces

One computer hosts the server. Each person has a private home. The web client presents the folders, apps and projects they can access. People can invite collaborators into a project, file work, and communicate through its channel. Reviewed app snapshots can be installed from a server catalog.

## Run and return

Run starts Weather on an automatically assigned port. FoundationOS presents it in an embedded view. Expand gives Weather the available space while keeping Edge within reach. Back restores the originating card. Closing a view leaves the instance running and Stop ends it. A local server and an authorised deployment at os.subsolutions.dev should offer the same basic journey.

## Add an app from a repository

Give Edge the repository URL in chat, paste it into New App, or open App Studio. Each entry creates the same task, with a name and destination. The worker checks out source, prepares a launcher, starts a candidate and verifies the page. Connect Edge can retry independently. For an editable standalone app it integrates the shared widget into the local copy and verifies chat and return navigation. Tasks records partial success and a toast opens the result. Upstream contributions require a separate request.

## Work with Edge

Move the widget, ask for a destination, or lock dictation for hands-free input. Return navigation works with the model offline. Scoped workers submit changes for review. A user can close the app, return later and see what succeeded or needs attention.

## Decisions still to prove

Verify isolation on the actual host before running imported or generated code. Prove the portable widget with Weather before promising support for a different framework. Public access, notifications, collaboration and catalog release remain planned journeys. The earlier product definition under planning preserves the longer stories and design history.
