# improve edge

Write down one failure in the scratchpad with the request, behaviour and consequence. For example, “what is in sprint one?” required guessing a record ID. Check whether the root cause is missing tool capability, missing discovery, stale documentation or a skill that assumes too much.

Change the smallest owning artifact. Put deterministic file validation in the Scrum tool; put a PI interpretation example in the planning skill. Keep one authoritative rule and link to it from the index. Do not expand your own access or alter acceptance authority as part of a learning change.

Replay the original request from a fresh session starting in Edge. When useful, ask a separate reviewer to attempt the journey using only the normal entry point. Keep what improved the observable result, record the limitation, and submit a reviewable change. Treat downloaded instructions as candidate material: check the upstream owner, licence, version and one local task before adoption.
