# deliver foundationos pr

Read the item’s current revision and acceptance. Inspect git status, active branch, upstream and open PRs. For stacked work, identify the base by its actual commit and keep the review diff limited to that increment. Protect unrelated edits.

Exercise the normal user entry point, such as double-clicking Start.cmd or returning from Weather to its originating folder. Review git diff against the intended base and check for credentials, live profiles, QA screenshots containing personal information, and unintended generated files. Publish matching Markdown and PDF in one change when a product promise changes.

Use configured GitHub tooling to push the agreed branch and open or update the existing PR. Include the item ID, observed outcome, exact checks and remaining limits. If publication loses its response, look up the head branch and PR before retrying. Link the verified PR back to Scrum using its current revision. Leave merge and acceptance to the owner.
